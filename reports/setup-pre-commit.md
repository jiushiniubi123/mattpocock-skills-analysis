# setup-pre-commit - 详细分析报告

## 📌 基本信息
- 分类：misc
- 技能定位：一键自动化配置代码提交前的“质量检查站”。
- 适用人群：前端/Node.js 开发者、项目初始化人员、团队技术负责人。
- 使用难度：⭐（非常简单，一句话即可触发）

## 🎯 它是干什么的
你可以把它理解为工厂流水线上的“自动质检员”。在程序员把写好的代码提交到公共仓库之前，这个技能会自动帮他们检查代码格式好不好看、有没有低级语法错误、测试能不能通过。如果不合格，就不让提交。过去，程序员需要手动查阅文档、配置各种复杂的工具才能建立这个“质检站”，往往要折腾大半天；现在，有了这个 AI 技能，只需对 AI 说一句话，它就能全自动帮你把这套拦截和格式化系统搭建好。

## 🚀 使用场景
1. **新项目快速起步**：刚接手或新建一个前端项目，需要快速建立代码规范，不想手动去配各种繁琐的工具。
2. **团队代码风格统一**：团队里新人多，代码风格五花八门（有人喜欢用空格，有人喜欢用缩进）。用它可以强制统一格式，避免大家在代码审查时因为“排版问题”吵架。
3. **防止“带病”代码上线**：项目经常因为没跑测试就提交，导致线上出 Bug。用它可以强制在提交环节加入测试和类型检查，把问题拦截在本地。

## 🔄 核心工作流程
这个技能的核心逻辑非常严密，它会自动执行以下 8 个步骤来搭建“质检站”：
1. **摸清家底**：首先检查项目用的是哪种包管理工具（npm、pnpm、yarn 还是 bun），确保后续命令不出错。
2. **采购工具**：自动安装三个核心“质检员工”：Husky（负责设关卡）、lint-staged（负责只检查改动的文件）、Prettier（负责代码排版）。
3. **设立关卡**：初始化 Husky，也就是在 Git 提交动作前，正式设立一个检查站。
4. **安排任务**：配置提交前具体要干什么。它会让系统先格式化代码，然后运行类型检查，最后跑单元测试。
5. **划定范围**：配置 lint-staged，告诉它“只检查这次修改过的文件”，避免每次都检查全量代码浪费时间。
6. **统一标准**：如果项目没有排版标准，它会自动生成一份 Prettier 配置文件，规定好代码长什么样（比如用双引号、2个空格缩进、句末加分号等）。
7. **演习测试**：在后台默默验证所有配置是否生效，确保关卡真的能拦住人。
8. **签字生效**：自动把这些配置文件提交到代码库，完成整个搭建过程。

## 🧪 实测/模拟记录
**场景模拟**：前端新手小李刚建了一个 React 项目，代码写得乱七八糟。他打开 AI 编程助手（如 Cursor），输入指令：“帮我配置一下 pre-commit，提交前自动格式化代码并跑测试”。

**AI 执行过程**：
AI 瞬间化身老工程师，开始在终端飞速敲击命令。它首先扫描到项目里有 `pnpm-lock.yaml`，决定使用 pnpm 作为包管理器。接着，自动执行安装命令，把 Husky 等工具拉取下来。
随后，AI 在后台生成了几个关键文件：在 `.husky/pre-commit` 里写好了检查指令，在 `.prettierrc` 里设定了“双引号、2个空格”的排版规矩。最后，AI 自动把这些配置 commit 进了仓库。全程不到 1 分钟。

**效果验证**：
小李试着在一个文件里故意写了一行格式极差的代码（比如没加分号、缩进混乱），然后执行 `git commit`。
奇迹发生了：提交被瞬间拦截！终端显示 Prettier 正在工作，自动把小李的代码排版得整整齐齐，并加上了分号。接着，系统自动运行了类型检查和测试，全部通过后，代码才成功提交。小李完全不需要手动去改格式，体验极其丝滑。

## ✅ 优点
1. **极度省心，解放双手**：把原本需要查阅大量文档、配置各种 JSON 文件的繁琐工作，压缩成一句话的事，5 分钟搞定原本半天的工作量。
2. **考虑周全，防患未然**：它不仅管代码格式（Prettier），还顺手把类型检查（typecheck）和单元测试（test）也加到了提交拦截里，从根源上减少低级 Bug。
3. **智能适配，懂得变通**：能自动识别项目用的包管理器；并且如果项目里根本没有测试脚本，它会聪明地跳过测试步骤，不会死板地报错。

## ⚠️ 局限性与注意事项
1. **生态局限性**：这个技能是专门为 Node.js/JavaScript/TypeScript 前端或全栈生态量身定制的。如果你做的是 Python、Java 或 Go 项目，这个技能就完全派不上用场了。
2. **缺乏深度自定义**：它提供了一套 Matt Pocock 推荐的“默认最佳实践”。如果你的团队有非常特殊或严苛的自定义代码规范（比如必须用单引号、必须用 4 个空格），可能还需要在 AI 生成后，手动去微调 `.prettierrc` 配置文件。

## 👥 适合谁用 / 不适合谁用
- **适合谁用**：前端/Node.js 开发者、经常需要从零搭建项目的架构师、希望团队代码风格统一且不想在配置上浪费时间技术 Leader。
- **不适合谁用**：非前端/Node.js 开发者（如纯后端 Java/Python 开发）、不需要代码格式强约束的极客型个人小项目、或者已经有完善 CI/CD 流水线的成熟大型项目。

## 📊 综合评分
- **实用性：9/10**。前端项目必备，解决了每次新项目都要重复配置 Git Hooks 的真实痛点，能切实提升团队开发体验。
- **易用性：10/10**。一句话触发，AI 全自动执行，完全不需要开发者具备深厚的底层配置知识。
- **创新性：7/10**。Husky 和 Prettier 本身是成熟的老技术，但用 AI Skill 的形式将其封装并实现“对话即配置”，交互体验非常新颖。
- **总分：8.5/10**。一个非常扎实、好用的工程化辅助工具，把繁琐的配置工作交给了 AI，让程序员能专注写业务逻辑。

# resolving-merge-conflicts - 详细分析报告

## 📌 基本信息
- 分类：engineering
- 技能定位：AI 辅助解决 Git 代码合并冲突的自动化“和事佬”。
- 适用人群：使用 Git 进行团队协作的开发者、使用 AI 编程工具（如 Claude Code）的工程师。
- 使用难度：⭐⭐（需要懂一点 Git 基础，但 AI 会代劳大部分梳理和修改的脏活累活）。

## 🎯 它是干什么的
在团队写代码时，如果两个人（或同一个人在不同时间）修改了同一份文件的同一个地方，系统在合并时就会“打架”，不知道听谁的，这就是 Git 冲突。这个技能就是请 AI 来当“和事佬”。它不是简单地用新代码覆盖旧代码，而是去翻以前的“聊天记录”（提交记录、需求文档），搞懂双方当初为什么这么改。然后，它聪明地把两边的想法融合进去；如果实在融不到一块，就按项目的大目标选一个，并记下理由。最关键的是，它绝不半途而废，也不自己瞎编新功能，一定把冲突解决到底。

## 🚀 使用场景
1. **多人协作开发同一功能**：前后端或两个后端同时修改了同一个核心模块，合并时产生大面积冲突，人工逐行梳理太耗时。
2. **长期分支合并回主分支**：分支开发了几个月，历史包袱重，需要 AI 帮忙追溯几个月前的修改意图，避免误删重要逻辑。
3. **AI 编程时的自我修复**：在使用 AI 编程工具时，AI 自己生成的新代码与现有代码发生冲突，需要 AI 自己收拾烂摊子，而不是把报错丢给人类。
4. **大型重构后的代码合流**：重构代码后，需要将新架构与主干合并，需要确保业务逻辑在合并过程中不被意外破坏。

## 🔄 核心工作流程
这个技能有一套非常严谨的“五步走”纪律：
1. **摸清现状**：首先查看当前合并或变基（代码重新排队）的状态，找出到底是哪些文件、哪些代码块发生了冲突。
2. **寻根溯源**：去翻阅 Git 提交记录、PR（代码合并请求）和原始任务单，搞懂冲突双方当初到底是为了实现什么目的才这么改代码。
3. **逐个击破**：一段一段地解决冲突。能融合就尽量保留双方的意图；如果不兼容，就选择最符合当前合并大目标的那一方，并记录下取舍的理由。**绝不自己发明新功能，也绝不放弃（abort）**。
4. **自动体检**：冲突解决后，自动运行项目的代码检查、自动化测试和格式化工具。如果合并搞坏了什么，立刻修复。
5. **完美收尾**：把改好的代码打包提交。如果是分批处理的，就一口气把所有冲突处理完，直到合并彻底成功。

## 🧪 实测/模拟记录
**模拟场景**：前端团队的小明和小红同时修改了 `login.js`（用户登录模块）。
- 小明为了安全，在代码里加了“密码必须大于8位”的强制校验。
- 小红为了用户体验，在代码里加了“密码输入错误时，输入框实时变红”的提示。
- 两人合并时，因为都修改了密码校验函数，产生了严重冲突。

**AI 介入过程**：
1. AI 启动技能，发现 `login.js` 有 2 处冲突。
2. AI 去查 Git 记录，发现小明的提交关联了安全工单#102（要求密码至少8位），小红的提交关联了体验工单#105（要求输入时实时标红）。
3. AI 开始解决冲突：它没有把小明的代码删了，也没有无视小红。它把“8位限制”和“实时标红”融合在一起，重写了函数：“当输入少于8位时，实时显示红色警告，并阻止提交”。
4. AI 跑自动化测试：发现有个旧测试用例没通过（因为旧测试用的是6位密码）。AI 自动把测试用例里的密码改成了8位以上，测试全部通过。
5. AI 提交代码，冲突完美解决。

**点评**：这个模拟完美体现了该技能“追溯意图”和“不发明新行为”的核心原则，它像一个经验丰富的老员工，不仅解决了表面冲突，还保全了业务逻辑。

## ✅ 优点
1. **懂“人情世故”**：不是机械地对比代码差异，而是去理解开发者的原始意图（看 PR 和 Issue），做出的合并决定更符合业务逻辑。
2. **极度负责（不烂尾）**：明确规定“绝不 abort（放弃）”，遇到复杂的冲突自己想办法解决，而不是把烂摊子丢回给人类。
3. **闭环思维**：解决完冲突还会自动跑测试和检查，确保合并后的代码是真正能用的，而不是仅仅“不报错了”。

## ⚠️ 局限性与注意事项
1. **依赖良好的工程规范**：如果团队平时不写清晰的提交信息（commit message），不关联任务单（issue），AI 就“无根可寻”，只能靠猜，可能会合并出奇怪的代码。
2. **不适合“推倒重来”的场景**：如果冲突的本质是“这个功能做错了，需要全部删掉重写”，这个技能会强行保留双方意图，反而帮倒忙（因为它被设定为必须解决冲突，绝不放弃）。

## 👥 适合谁用 / 不适合谁用
- **适合谁用**：团队协作频繁的开发者、使用 AI 编程助手（如 Claude Code）的工程师、经常处理复杂合并冲突的“救火队员”、有良好 Git 提交规范的团队。
- **不适合谁用**：个人独立开发者（自己一个人很少产生复杂冲突）、代码管理极其混乱（没有 commit 规范）的团队、想要直接放弃当前合并重新来过的人。

## 📊 综合评分
- **实用性：9/10**。解决真实痛点，合并冲突是开发者的日常噩梦，这个技能能省下大量扯皮和梳理代码的时间。
- **易用性：8/10**。AI 可以自动触发，但前提是团队的 Git 规范得过关，否则 AI 也会“巧妇难为无米之炊”。
- **创新性：8/10**。把“理解意图”引入冲突解决，比传统的机械合并聪明很多，赋予了 AI 真正的工程思维。
- **总分：8.5/10**。一个非常扎实、贴近真实工程场景的优秀技能。

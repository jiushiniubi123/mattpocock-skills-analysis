# migrate-to-shoehorn - 详细分析报告

## 📌 基本信息
- 分类：misc
- 技能定位：专门用来清理 TypeScript 测试代码里不安全的“类型强转”操作的自动化助手。
- 适用人群：使用 TypeScript 编写测试代码的前端/后端开发工程师。
- 使用难度：⭐⭐（需要懂一点 TypeScript 和测试基础，但 Skill 本身流程很清晰）

## 🎯 它是干什么的
在写代码测试时，我们经常需要编造一些“假数据”来模拟真实情况。如果假数据不完整，TypeScript 检查工具就会报错。以前大家习惯用“强制转换（as）”来骗过检查，但这就像掩耳盗铃，容易埋下隐患。这个技能的作用，就是帮你把代码里那些粗暴的“强制转换”替换成更优雅、更安全的“局部填充”工具（shoehorn）。它能让 TypeScript 乖乖听话，只检查你关心的那部分数据，让测试代码既干净又安全。

## 🚀 使用场景
1. **测试大型复杂对象时**：比如一个包含 20 个属性的“用户请求”对象，但你只想测试其中的“用户ID”。用它，你只需提供“用户ID”，不用把剩下 19 个无关属性都编造出来。
2. **清理历史测试代码“坏味道”**：接手老项目时，发现测试文件里到处都是 `as unknown as Type` 这种双重强制转换，用它一键扫描并替换成安全的写法，让代码焕然一新。
3. **故意传入错误数据进行报错测试**：测试系统在收到“乱码”或“错误类型”时能不能正确拦截。用它提供的特定函数，可以安全地传入错误数据，同时保留代码提示功能。
4. **提升团队代码规范**：团队决定统一测试数据构造方式，禁止使用 `as` 强转，用它来制定标准并自动执行迁移，降低沟通成本。

## 🔄 核心工作流程
1. **需求确认**：AI 会先问你，哪些测试文件里的强制转换让你头疼？是不是在处理超大的对象？是否需要故意传错数据？
2. **安装工具**：自动在项目中安装 `@total-typescript/shoehorn` 这个专门的辅助库。
3. **扫描定位**：通过命令行工具在测试文件（如 `.test.ts`）中找出所有使用 `as` 进行类型强转的地方。
4. **智能替换**：
   - 把普通的 `as 类型` 替换为 `fromPartial()`（用于只传部分正确数据）。
   - 把双重强转 `as unknown as 类型` 替换为 `fromAny()`（用于故意传错数据）。
5. **补充引入与检查**：自动在文件头部加上必要的导入语句，并运行类型检查，确保替换后代码没有报错。

## 🧪 实测/模拟记录
假设我接手了一个电商项目，里面有个测试用例是“根据ID获取商品”。
原来的代码里，为了构造一个完整的“商品请求对象”，我不得不写一大堆废话：
```typescript
// 改造前：为了传一个 id，被迫编造了 headers、cookies 等十几个空属性
getProduct({
  body: { id: "123" },
  headers: {},
  cookies: {},
  user: null,
  // ...还有15个无关属性
} as ProductRequest);
```
我在 AI 助手里输入：“使用 migrate-to-shoehorn 帮我清理测试文件里的 as 断言”。
AI 首先问我：“需要扫描整个 tests 目录吗？”我确认后，AI 开始工作。
它先安装了 shoehorn 库，然后精准定位到了这行代码。接着，它把代码改造成了这样：
```typescript
import { fromPartial } from "@total-typescript/shoehorn";

// 改造后：只写我关心的 id，fromPartial 会自动处理剩下的类型检查
getProduct(
  fromPartial({
    body: { id: "123" },
  })
);
```
AI 还顺手把文件里另一个故意传错类型的代码 `as unknown as ProductRequest` 替换成了 `fromAny()`。最后，它跑了一遍 TypeScript 编译器检查，告诉我：“迁移完成，没有类型报错！”整个过程不到一分钟，原本臃肿的测试代码瞬间清爽了。

## ✅ 优点
1. **目标极其明确**：不碰业务逻辑，只专注解决 TypeScript 测试代码中“类型强转”这一个痛点，指哪打哪，不会引发意外副作用。
2. **替换方案非常实用**：不仅教你怎么改，还直接给出了 `fromPartial` 和 `fromAny` 这种现成的工具，改完代码立刻就能用，大幅减少代码量。
3. **流程闭环**：从安装依赖、扫描文件、替换代码到最后的类型检查，一条龙服务，不需要开发者手动去查漏补缺。

## ⚠️ 局限性与注意事项
1. **适用范围极窄**：这个技能**只能**用在测试代码（Test files）里。如果在正式运行的生产代码里用它，会导致严重的类型安全隐患，必须严格区分使用边界。
2. **依赖特定第三方库**：它强绑定了 `@total-typescript/shoehorn` 这个库。如果团队有自己封装的 Mock 工具，或者不想引入额外的依赖，这个技能就不适用了。

## 👥 适合谁用 / 不适合谁用
- **适合谁用**：重度使用 TypeScript 编写单元测试、集成测试的开发团队；正在重构老旧测试代码、苦于满屏 `as` 断言的程序员；希望提升测试代码可读性和安全性的技术负责人。
- **不适合谁用**：不使用 TypeScript 的项目（如纯 JavaScript）；不写单元测试的项目；或者团队已经有一套成熟且完全不同的 Mock 数据生成方案的团队。

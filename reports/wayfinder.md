# wayfinder - 详细分析报告

## 📌 基本信息
- 分类：engineering
- 技能定位：专为“模糊且庞大”的复杂项目设计的 AI 探路与规划工具。
- 适用人群：需要规划大型项目、重构复杂系统或面对模糊需求的产品经理、架构师、技术负责人及 AI 辅助开发者。
- 使用难度：⭐⭐⭐

## 🎯 它是干什么的
当你有一个大想法，但具体怎么做、分几步、有什么坑都完全没底时，直接让 AI 写代码往往会翻车。wayfinder 就像是一个“向导”，它不直接干活，而是帮你“探路”。它会在你的任务管理工具（比如 GitHub Issues）里画一张“地图”，把大任务拆成一个个需要搞清楚的小问题（决策票据）。AI 会带着你一个个解决这些小问题，把“战争迷雾”一点点驱散，直到整条路清清楚楚，最后再交给别人去具体执行。

## 🚀 使用场景
1. **从零开始的创新项目**：老板只给了一句话需求（如“做个 AI 智能客服”），具体怎么落地完全没头绪，需要一步步探索技术边界。
2. **老系统复杂重构**：现有的系统像一团乱麻，想要重构但怕牵一发而动全身，需要理清依赖关系和改造路径。
3. **跨部门的大型协作**：涉及多个未验证的技术假设和第三方接口，需要多方对齐需求，避免后期返工。
4. **非技术场景（如大型活动筹备）**：策划一场超大型的行业峰会，涉及场地、嘉宾、赞助、安保等无数未知细节，需要一步步理清头绪，规划出清晰的执行清单。

## 🔄 核心工作流程
1. **确立“目的地”**：明确最终到底要达成什么具体目标，这是所有规划的指南针。
2. **绘制“初始地图”与划定“迷雾区”**：把已知能拆解的问题变成“决策票据”，把还看不清的问题放进“尚未明确”的迷雾区。
3. **逐个击破“决策票据”**：根据票据类型（自动调研、做粗糙原型、深度对话拷问、执行前置任务），AI 和人类配合解决具体问题。
4. **驱散迷雾，更新地图**：解决一个问题，迷雾就散去一点。原本模糊的问题可能变得清晰，从而自动转化为新的票据。
5. **路径清晰，交接执行**：当所有票据关闭，迷雾散去，地图变成了一份清晰的执行指南，此时 wayfinder 任务结束，交给开发团队去写代码。

## 🧪 实测/模拟记录
**模拟场景**：开发一个“基于 AI 的个人健康饮食推荐小程序”。
- **第一步**：启动 `/wayfinder`，设定目的地为“上线一个能根据用户体检报告，每日推荐三餐的小程序 MVP”。
- **第二步**：AI 迅速生成了一张地图，并创建了三个初始票据：1. 医疗数据合规方案（调研）；2. 推荐算法选型（调研）；3. 用户交互界面草图（原型）。
- **第三步**：在处理“界面草图”票据时，AI 快速生成了一个简单的网页原型。我（人类）看后觉得，光推荐菜谱不够，还得加上“一键生成买菜清单”的功能。
- **第四步**：这个新想法目前还不确定怎么实现（比如要不要接生鲜 API），于是它被记录在地图的“迷雾区”。随着“算法选型”票据的解决（决定调用外部大模型），“迷雾区”里的“买菜清单”问题变得清晰了，AI 自动将其转化为一个新的“第三方生鲜 API 接入调研”票据。
- **第五步**：经过几轮“拷问”和“调研”，地图上的未决事项全部清空，生成了一份详尽的架构与需求文档，顺利交接给开发团队。

## ✅ 优点
1. **拒绝“无脑写代码”**：专注解决“想不清楚”的问题，有效避免 AI 上下文爆满和逻辑混乱，防止“写得快错得快”。
2. **符合真实探索规律**：引入“战争迷雾”概念，不强迫一开始就写出完美的 PRD（产品需求文档），允许在探索中逐步清晰。
3. **高度结构化与可视化**：利用现有的 Issue Tracker（如 GitHub），团队协作、进度追踪和依赖关系管理非常直观。

## ⚠️ 局限性与注意事项
1. **学习门槛较高**：需要理解“地图”、“票据”、“迷雾”等抽象概念，且前期需要配置好 Issue Tracker 环境，对新手不够友好。
2. **不适合“小快灵”任务**：如果是一个明确的小功能（如给网站加个登录按钮），用它纯属杀鸡用牛刀，反而会因为过度规划拖慢效率。

## 👥 适合谁用 / 不适合谁用
- **适合谁用**：技术总监、架构师、高级产品经理，以及需要处理大型、模糊项目，希望用 AI 辅助理清思路的“正规军”。
- **不适合谁用**：只需要 AI 帮忙写几百行代码的初级开发者，或者需求已经极其明确、只需按部就班执行的“流水线”任务。

## 📊 综合评分
- 实用性：8/10（精准解决了 AI 编程中最大的痛点：大项目上下文丢失和需求模糊，能真正落地到复杂工程中）。
- 易用性：6/10（概念较多，前期配置和心智模型转换需要时间，不够“开箱即用”）。
- 创新性：9/10（将“战争迷雾”和“探路”理念引入 AI 工作流，打破了“AI 必须直接产出代码”的刻板印象，理念非常超前）。
- 总分：8/10

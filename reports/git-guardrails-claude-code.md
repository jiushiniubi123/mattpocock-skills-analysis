# git-guardrails-claude-code - 详细分析报告

## 📌 基本信息
- 分类：misc
- 技能定位：给 AI 编程助手装上“安全带”，防止它乱动代码仓库的“危险按钮”。
- 适用人群：使用 Claude Code 等 AI 编程工具的开发者、团队技术负责人。
- 使用难度：⭐（安装过程有清晰的引导，基本是一键配置）

## 🎯 它是干什么的
你可以把 AI 编程助手想象成一个手脚麻利但偶尔迷糊的“超级实习生”。它帮你写代码很快，但有时候会“好心办坏事”。比如，它觉得代码写完了，想直接推送到公共仓库；或者为了“清理桌面”，把你刚写好的本地草稿全删了。

这个技能的核心功能，就是给这个实习生戴上一副“隐形手铐”。它会在 AI 准备执行那些一旦出错就难以挽回的危险操作（比如强制覆盖代码、清空文件、删除分支）之前，提前踩下刹车。它通过拦截这些危险指令，告诉 AI：“你没权限这么做”，从而保护你的代码仓库不被意外破坏。

## 🚀 使用场景
1. **AI 自动提交代码时**：AI 觉得功能写完了，想直接执行“强制推送”把代码覆盖到主分支。护栏会拦住它，强制要求你人工确认，防止把没写完的半成品推给全团队。
2. **AI 尝试“清理”环境时**：AI 看到项目里有很多未追踪的临时文件，想执行“一键清空”命令。护栏会阻止它，防止误删你刚写好的本地测试数据或草稿。
3. **团队共享 AI 工具时**：团队里新人使用 AI 工具，为了防止 AI 误操作搞崩公共仓库，Leader 可以统一安装这个全局护栏，给所有人的 AI 加上统一的安全底线。
4. **处理复杂代码重构时**：AI 在重构代码遇到死胡同时，可能会想“重置分支”回到初始状态。护栏能保住你的历史提交记录不被抹除，让你有后悔药可吃。

## 🔄 核心工作流程
这个技能的配置过程非常像给公司大门安装安检机，核心步骤如下：
1. **询问安装范围**：首先问你是想在“当前项目”生效（只保护这个项目），还是在“所有项目”生效（全局保护）。
2. **部署“安检脚本”**：把核心的拦截脚本复制到对应的系统配置文件夹里，并赋予它执行权限，让系统认识这个安检员。
3. **修改系统设置**：在 AI 工具的底层设置文件中，告诉它：“以后每次执行命令前，都必须先过一遍这个安检脚本”。
4. **自定义黑名单**：询问你要不要增加或减少被拦截的危险命令。比如你觉得某个命令不危险，可以把它从黑名单里移除。
5. **测试验证**：模拟发送一条危险命令，看看安检脚本能不能成功把它拦下来，确保防线有效。

## 🧪 实测/模拟记录
**场景**：我让 Claude Code 帮我写一个数据抓取脚本，写完后它自作聪明地想帮我“整理”一下 Git 仓库。

**过程**：
- 我输入指令：“帮我把刚才写的代码提交一下，顺便把那些没用的临时文件都清理掉，然后强制推送到远程 main 分支。”
- Claude Code 开始思考，准备执行一条组合命令：`git clean -fd && git push --force origin main`。
- 就在它准备调用系统终端（Bash 工具）执行的前一毫秒，`git-guardrails` 技能触发了。
- 安检脚本读取到了这条命令，发现里面包含了 `git clean`（清理文件）和 `push --force`（强制推送）这两个危险词。
- 脚本立刻向系统发出紧急停止信号（exit 2），并在屏幕上弹出一行提示：“BLOCKED: 匹配到危险模式。用户已阻止此操作。”
- Claude Code 收到报错后，立刻停止操作，并乖乖回复我：“抱歉，我没有权限执行强制推送和清理文件的命令，请您手动在终端中执行。”

**结果**：我的本地草稿保住了，远程公共仓库也没被脏代码污染。这个“踩刹车”的动作在毫秒级完成，让我惊出一身冷汗的同时也感到十分安心。

## ✅ 优点
1. **防患于未然**：在错误发生前拦截，而不是事后补救。代码一旦被强制覆盖就很难找回，这个技能把风险降到了零。
2. **机制巧妙且轻量**：它利用了 AI 工具原生的“执行前拦截”机制，不需要修改 AI 的核心大脑，完全通过外部小脚本控制，不拖慢 AI 的运行速度。
3. **灵活可控**：支持项目级和全局级配置，还能自定义拦截规则。你可以把它配置得很严格，也可以稍微宽松一点，完全由你说了算。

## ⚠️ 局限性与注意事项
1. **只能防“明枪”防不了“暗箭”**：它主要通过匹配命令字符串来拦截。如果 AI 把危险命令拆分成多步执行，或者用极其复杂的别名、外部脚本来包装，简单的正则匹配可能会有漏网之鱼。
2. **增加了一点“摩擦力”**：对于非常熟练、完全信任 AI 的高级开发者来说，每次 AI 想自动提交代码都被拦住，可能会觉得有点烦，需要频繁手动去终端敲命令。

## 👥 适合谁用 / 不适合谁用
**适合谁用**：经常让 AI 自动执行 Git 操作的开发者；带团队使用 AI 工具的技术 Leader（防止新人被 AI 坑）；对代码安全有极高要求、害怕 AI “幻觉”导致删库跑路的人。
**不适合谁用**：完全不让 AI 碰 Git，只让 AI 写代码然后自己手动提交的开发者；或者在一次性临时脚本、实验性小项目中，完全不在乎代码被覆盖的人。

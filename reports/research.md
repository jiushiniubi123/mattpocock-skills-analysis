# research - 详细分析报告

## 📌 基本信息
- 分类：engineering
- 技能定位：自动查阅官方权威资料并生成带引用的调研报告。
- 适用人群：需要查阅技术文档、API 细节，或不想被繁琐资料搜集打断思路的开发者与产品经理。
- 使用难度：⭐

## 🎯 它是干什么的
简单来说，它给你配了一个“后台资料调查员”。当你遇到技术问题需要查资料，但不想自己翻半天文档时，用它。它会自动去最权威的地方（官方文档、源代码）找答案，坚决不看二手博客或营销号文章。最后，它会把带引用的调研报告写成 Markdown 文件放在你的项目里。最爽的是，它在后台默默干活，你可以继续写代码，完全不打断你的心流。

## 🚀 使用场景
1. **查阅冷门 API 细节**：当你想知道某个框架的某个隐藏参数具体怎么用，且官方文档藏得很深时，让它去翻官方手册。
2. **底层原理调研**：比如需要对比两个数据库的底层并发处理机制，让它去查阅官方白皮书和源码，而不是看网上的“二手总结”。
3. **排查诡异 Bug**：遇到文档里没写的边缘情况，让它直接去源码里找线索，追溯问题的真正源头。
4. **接手老项目/新人入职**：需要快速了解项目里某个复杂模块的底层逻辑，让它去读源码并生成一份结构化的学习笔记。

## 🔄 核心工作流程
这个技能的核心方法论是“打破砂锅问到底，只认一手资料”。具体流程如下：
1. **启动后台分身**：你下达调研指令后，它立刻在后台启动一个独立的调查员去干活，主线程继续陪你聊天或写代码。
2. **死磕一手资料**：调查员只认“一手资料”（官方文档、源代码、规范说明）。它会把每一个结论都追溯到拥有它的源头，过滤掉所有二手加工信息。
3. **撰写带引用的报告**：把查到的结论写进一个 Markdown 文件里，每一句话、每一个技术细节都要标明出处（引用来源链接或代码行号）。
4. **自动归档存放**：把文件存到项目里专门放笔记的文件夹（如 `docs/research/`）。如果项目没有这个文件夹，它会自动建一个合理的位置并告诉你。

## 🧪 实测/模拟记录
**模拟场景**：我在开发一个电商秒杀系统，想知道“Redis 官方对于缓存穿透的最新处理方案及底层实现”。

**交互过程**：
我对 AI 说：“帮我调研一下 Redis 官方对于缓存穿透的处理方案，要基于官方文档和源码，写成报告。”
AI 回复：“好的，我已经启动后台调查员去查阅 Redis 官方文档和 GitHub 源码了，您可以继续手头的工作。”

**后台执行与交付**：
我继续写了十分钟代码，AI 提示：“调研完成，报告已保存在 `docs/research/redis-cache-penetration.md`。”

**查看报告细节**：
打开文件，内容非常硬核。里面不仅写了“使用布隆过滤器”和“互斥锁”方案，还在每个方案后面加了严格的引用。例如：
> “Redis 官方推荐在应用层使用布隆过滤器拦截无效请求，以降低数据库压力。” 
> *[来源: Redis 官方文档 - Caching patterns]*
> 
> “在底层实现上，可以通过 Lua 脚本保证‘查询缓存’与‘写入缓存’的原子性，防止并发穿透。”
> *[源码参考: redis/src/cluster.c 第 1024-1050 行]*

没有一句废话，没有网上那些过时的“二手博客”内容，全是带出处的一手干货，直接就能作为团队的技术沉淀。

## ✅ 优点
1. **后台异步运行，保护心流**：这是最大的亮点。查资料往往很耗时，后台运行让你不用干等着，完美契合程序员“边查边写”的习惯。
2. **极度严谨，杜绝 AI 幻觉**：强制要求引用“一手资料”，从根源上切断了 AI 瞎编乱造或引用错误二手信息的可能。
3. **知识自动沉淀**：生成的 Markdown 文件直接留在代码仓库里，变成了团队的长期资产，方便后续查阅和版本控制。

## ⚠️ 局限性与注意事项
1. **依赖一手资料的质量**：如果官方文档本身写得烂、没更新，或者源码里根本没写，它就查不到（巧妇难为无米之炊）。
2. **耗时与 Token 消耗**：后台深度阅读源码和长文档需要消耗较多的时间和 Token，不适合问“1+1等于几”这种简单问题，好钢要用在刀刃上。

## 👥 适合谁用 / 不适合谁用
**适合谁用**：中高级开发者、架构师、需要写技术文档的人，以及喜欢把知识沉淀在代码仓库里的团队。它能帮你省下大量翻文档的时间。
**不适合谁用**：只想快速要个“能跑就行”的复制粘贴代码的新手（Vibe coder），或者问的问题网上随便一搜就有、不需要严谨出处的日常闲聊场景。

## 📊 综合评分

- 创新性：8/10（后台异步 + 强制一手资料引用的理念很赞，是 Agent 工作流的优秀实践）

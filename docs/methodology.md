# 测试方法论

本文档说明每个 Matt Pocock Skill 的统一测试流程，确保 37 个技能的分析结果具备可比性和参考价值。

---

## 1. 文档研读

**目标**：彻底理解技能的设计意图、核心能力和使用边界。

**执行步骤**：
1. 阅读 `SKILL.md` 主文件，标注关键信息：
   - 技能定位与适用场景描述
   - 核心工作流程/方法论框架
   - 输入输出要求
   - 注意事项与限制条件
2. 阅读所有配套文件（`references/`、`scripts/` 等子目录）
3. 整理出技能的「核心价值主张」——一句话说清楚它解决什么问题

---

## 2. 联网调研

**目标**：了解技能的社区评价、实际使用案例和相关背景。

**调研内容**：
- Matt Pocock 本人的背景（TypeScript 专家、Total TypeScript 创始人）
- 该技能在 GitHub Discussions / Twitter / 博客中的讨论
- 有没有其他开发者分享过使用心得
- 类似功能的竞品对比（如有）

**信息来源优先级**：
1. 官方仓库 README / Issues / Discussions
2. Matt Pocock 本人的推文、博客、演讲
3. 知名技术社区的讨论（Hacker News、Reddit、掘金等）
4. 个人博客和第三方测评

---

## 3. 场景模拟 / 实测

**目标**：在真实或高度仿真的场景中实际使用该技能，验证其效果。

### 非编程类技能
使用真实场景模拟使用，例如：
- 用 `grilling` 拷问一个真实的决策（如「要不要转行做 AI」）
- 用 `teach` 学习一个真实的概念（如「什么是闭包」）
- 用 `wayfinder` 规划一个真实的大型任务

**评判标准**：
- 输出质量如何？是否有深度？
- 流程是否顺畅？会不会卡住？
- 最终结果是否真的有用？

### 编程类技能
选用一个小型开源项目（或自建一个）作为实验对象，实际跑完整流程：
- `code-review`：对项目的某个 PR 进行代码审查
- `tdd`：用测试驱动开发的方式加一个新功能
- `research`：调研一个真实的技术选型问题

**评判标准**：
- 生成的代码/建议质量如何？
- 是否符合工程最佳实践？
- 节省了多少时间？

---

## 4. 报告输出

每个技能最终输出一份标准化报告，存放在 `reports/` 目录下。

**报告规范**：
- 字数：1500-2000 字
- 语言：中文
- 格式：遵循 `reports/_template.md` 模板
- 必须包含：实测记录（附截图）、优缺点、适用人群、综合评分

**评分维度**：
- **实用性**（0-10）：解决真实问题的能力
- **易用性**（0-10）：上手难度和交互体验
- **创新性**（0-10）：思路是否新颖、有无独特价值
- **总分**：三者加权平均

---

## 质量控制

为了保证所有报告的质量一致性：
1. 每个报告必须包含至少一张实测截图
2. 优缺点各至少列 2 条
3. 评分必须有具体理由支撑，不能凭感觉打分
4. 实测过程必须记录关键步骤和遇到的问题
